# Terminal display settings

Click the muted **palette button** on the right of the SSH server bar to open **Terminal appearance**. It configures every SSH terminal in the current browser origin, including split panes and retained terminals. A server connection is not required. The dialog preserves the current tab, traps keyboard focus, closes with Escape or an outside click, and restores focus to the button. Its size follows the viewport: `min(1120px, calc(100vw - 32px))` wide and `min(840px, calc(100vh - 24px))` tall, so it fits entirely on a 1366×768 laptop or a windowed 1280×720 host. Only the scheme list scrolls; the theme switch, reset/backup buttons, add button and preview stay visible. At 620 px of viewport height or less, the whole dialog scrolls instead.

- **Theme:** follow DSH (default for new preferences), dark or light. All three modes use the DSH terminal skin: #101418 background with #e6edf3 text for dark, #f7f8fa background with #1d2128 text for light. Existing saved dark/light choices are preserved. The 16 ANSI colors and the semantic-highlighting scheme stay unchanged; cursor and selection colors come from the DSH skin. Remote truecolor values are preserved.
- **Terminal background:** a color picker, HEX field and ↺ reset sit next to the theme badge in the Color scheme heading. They edit the theme the badge shows; switch the theme radio to edit the other one. Edits apply immediately to every terminal and to the preview; each theme's background is saved separately in local storage and synchronized across same-origin windows. ↺ appears only when the current theme's background has been customized and restores its DSH default: #101418 (dark) or #f7f8fa (light); it hides again after the reset. The two themes are independent. The controls stay usable while semantic highlighting is off. A custom background changes the background, its automatically chosen text color and the cursor block; the 16 ANSI colors and semantic-highlighting colors stay the same. Text color follows the background luminance using the DSH light/dark foreground, so dark backgrounds get light text and light backgrounds get dark text. The preview uses the selected theme's background.
- **Semantic highlighting:** off by default. Turning it off keeps the scheme list, add button and reset/backup buttons in place, dimmed and disabled; the scheme heading, theme badge and Terminal background control stay usable. The preview stays editable but plain — no semantic colors — while its background and text color still follow the current theme. The dialog height and list position do not jump, and saved configuration is kept. Existing explicit opt-in preferences are preserved on upgrade.
- **Color scheme:** a wide list, stored independently for dark/light themes. A theme badge beside the heading — Dark theme or Light theme, with a theme-colored dot — shows which scheme is being edited. Each entry groups its enable switch, name, color/HEX controls and case-sensitivity toggle on one line, with editable tags spanning the row below. The case-sensitivity toggle shows only the Aa icon; its on/off state comes from the pressed highlight and the same ~160 ms quick tooltip instead of a native title — "Case sensitive: on" or "off" — and it still appears when the toggle or the whole block is disabled. The list scrolls independently while the add button and preview stay visible. Each tag is a JavaScript regex source without `/` delimiters; ordinary keyword text works directly. The trailing input in each row only adds new tags: type there and press Enter. Clicking a tag edits it in place (Enter saves, Esc cancels, blur saves), and × deletes it. Invalid expressions remain drafts with inline feedback. There is no matching-mode dropdown. Unmodified defaults preserve the original semantic classifications; default keyword categories use readable keyword tags and structured categories expose their patterns. Up to 43 entries, 64 tags per entry, 512 characters per tag and 8192 total characters per entry are supported.
- **Ordering:** drag the left handle to reorder. A one-line hint above the list reads "Drag the left handle to reorder; click a tag to edit." Hovering or focusing a handle shows a quick tooltip after about 160 ms: "Drag with the mouse, or focus the handle and press Alt + ↑/↓ to reorder". Alt+Up/Down reorders while a handle is hovered (no click needed) or focused with Tab; in that context the dialog intercepts the browser default, so Chrome on macOS does not turn Option+↑/↓ into page scrolling, while a focused text field keeps its native behavior. While dragging, the source row becomes a dashed placeholder, a floating copy follows the pointer without rotation or scaling, the rows below slide open a gap, an accent line marks the drop position, and the list scrolls near its edges; the tooltip disappears on leave, blur, drag start or list scroll. A 6 px threshold keeps clicks working; Esc cancels and `prefers-reduced-motion` turns off the animation. While the released copy glides back, the target row is hidden but keeps its space, so only one floating copy is visible; the row reappears when the copy lands, and cancelling behaves the same. Dragging preserves tag edits and scheme identity. Only one unfinished custom entry can exist at a time: the add button stays disabled until it has a match tag, and adding scrolls to the new row and focuses its first tag input. Narrow windows wrap tags beneath the row controls.
- **Reset and backup:** adjacent buttons restore the current theme's entire default scheme (colors, patterns, switches and ordering) or download its full look as JSON. The JSON carries a `background` field (DSH default or custom) next to `theme` and `entries`, so one backup captures that theme's complete appearance. Restoring asks for confirmation in a small popover anchored to the button — it overlays the list instead of shifting the rows — and offers a one-click backup first. A completed backup shows a floating toast below the button; it disappears after about 3 seconds and does not move the list. The other theme is preserved. Backup does not upload data. Legacy colors and literal/whole-word rules migrate to equivalent regex patterns.
- **Editable preview:** starts with a short eight-line log excerpt: a cat of the application log, service start (INFO), disk 87% full with cleanup skipped (WARNING), a refused database connection (ERROR, Chinese detail quoted as "数据库连接被拒绝"), the successful retry (SUCCESS, "重试成功" quoted), an IPv6/MAC peer (INFO), log directory permissions, and a systemctl status check. The excerpt still covers every built-in highlight category, keeps common English log text, and uses CJK only as quoted string values. All eight lines fit without scrolling. Type directly into the colored box: a native textarea handles caret, selection, undo and text entry over an inert highlighted mirror, with no separate editor. Preview text is temporary and is not sent to the server.

Settings are saved locally under `dsh-ssh-ops.terminal-display.v1`, synchronized to other same-origin windows, and reused after restart. They are not stored on the SSH server or shared between devices. If local storage is blocked or full, changes remain usable in the current window but may not survive a reload. The previous experimental highlight preference is read when no display-settings record exists.

## Session-log highlighting is separate

The warning/error highlighting introduced in v0.4.0 applies to recorded text in the **Logs** tab and its search results. It colors whole lines using fixed heuristics, independently of Terminal appearance settings. The optional semantic highlighting described here applies to tokens in the **live terminal** and its appearance preview; it does not alter recorded logs or their viewer.

The default classifications also differ: the log viewer colors `WARNING` and `deprecated` lines amber, while the terminal's built-in rules classify words through their own semantic categories (for example `WARNING` is a warning, not an error). Terminal scheme colors and patterns are editable; the log viewer keeps its existing rules. The two renderers never decorate the same surface.

## Rendering boundaries

Only default-style xterm cells receive semantic foreground decorations. Existing remote ANSI foreground/background colors and font attributes take priority. The matcher joins automatic wraps and maps Unicode text back to xterm cell widths; it does not modify terminal bytes, copy/search text, session logs, or agent output. Alternate-screen applications such as editors are not decorated.

Highlighting is heuristic, not a complete shell parser or a full shell grammar. Custom prompts can be misclassified. IPv6 support covers common hexadecimal full/compressed forms, not every zone-ID or IPv4-mapped form. Quoted escape subrules, rainbow brackets, folding and links are outside this feature.

Work is coalesced over 60 ms with a **leading throttle**: later events do not restart the timer, so colours keep flowing during a scroll instead of waiting for the wheel to stop. Scrolling into history, resizing, leaving an alternate-screen application, or any repaint after a wheel/scrollbar movement triggers a rescan. xterm 5.5 deliberately suppresses `onScroll` for user wheel scrolling and scrollbar dragging, so the addon tracks the viewport position from render events and polls it every 250 ms as a fallback.

A scan is limited to 200 visible physical rows and **1024 decorations**; the decoration budget fills **from the bottom row up**, so the newest output keeps its colours and the oldest visible lines are left plain when a dense screen exhausts it. Logical reads stop at 16384 cells and wrapped-line backtracking at 256 rows; extreme lines can be partially highlighted. Unchanged rows reuse their markers/decorations. A worker result computed before a scrollback trim is rebased onto the shifted lines (only a result whose anchor row was itself trimmed is discarded and requested again). A decoration API failure disables highlighting for that terminal while keeping theme changes and terminal input/output available. The refresh and recovery strategy is described in [highlight-refresh-fix.md](highlight-refresh-fix.md).

All user regex matching runs in one shared background worker, including preview matching. Queued jobs coalesce per terminal/preview. Matching has a 150 ms deadline after worker startup; a timed-out worker is terminated and that exact scheme is quarantined for 30 seconds, or until the colour scheme is edited (editing clears every quarantine). Other valid schemes can continue in a replacement worker. Releasing a terminal never retires the shared worker while another terminal still holds a lease, so switching tabs or disposing a pooled terminal does not stall the others. A failed scan keeps the last good decorations, reports the cause once, and backs off (500 ms doubling to 5 s) instead of clearing and rescanning every 60 ms. Input and theme changes remain available. If the host cannot create the worker, highlighting stays unavailable with a preview message; regex execution never falls back to the UI thread. The worker bundle is embedded in the client build and has no separate network route or runtime package dependency.

The default ANSI palettes and classification rules are designed in-house for this project (see [implementation review](terminal-appearance-cleanroom.md) and [third-party notices](../THIRD_PARTY_NOTICES.md)); the terminal chrome (background, text and cursor) follows the DSH terminal theme. The semantic palette keeps at least 4.5:1 contrast on each theme's DSH background — enforced by `test/terminal-appearance-contrast.mjs` — while user overrides and server truecolor values are unrestricted.

## Validation

```sh
node --test test/output-highlight.mjs test/terminal-display-settings.mjs test/regex-worker.mjs test/highlight-refresh.mjs test/highlight-drag-order.mjs test/preview-text.mjs test/terminal-appearance-semantic.mjs test/terminal-appearance-contrast.mjs test/terminal-appearance-migration.mjs
npm test
npm run lint
npm run build
git diff --check
```

The feature tests use the real xterm buffer and real worker threads: ANSI/truecolor/styles, wrapped lines, wide-character wrap padding, Chinese/emoji/combining characters, carriage-return overwrites, alternate screen, resize/zoom, bounded scrollback, disposal, failure isolation, persistence, migration, per-theme schemes, regex/Unicode matching, zero-length matches, catastrophic-pattern deadlines, queue coalescing, recovery, entry switches, reset/export and cross-window ordering. The feature files listed above also cover refresh/recovery, drag-order geometry and the preview seed text, which exercises every built-in category and includes CJK characters. They are included in `npm test` and the existing CI matrix.

For browser/DSH acceptance, check follow-DSH and both fixed themes with highlighting on/off, add/edit/delete regex tags, drag entries and use keyboard ordering, test timeout/recovery, restore/export the current theme, verify that the other theme survives reset, edit preview text with undo and scrolling, check Escape/outside-click closing and focus restoration, switch DSH's outer theme, search/select/copy terminal text, resize and split panes, switch tabs/reopen retained terminals, and reload or restart to check persistence. Validate narrow sidebars and both UI languages. Browser component checks do not replace an end-to-end run inside the DSH host.
