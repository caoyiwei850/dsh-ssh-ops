# DSH SSH Ops 产品文档

> 在 DSH 主对话里指挥服务器干活，右侧始终留着一台真实交互终端——外加文件管理、端口转发、数据库操作与多机批量执行，全部在一个插件里。

**版本 0.3.22** · MIT 协议 · [GitHub 仓库](https://github.com/caoyiwei850/dsh-ssh-ops) · [Releases](https://github.com/caoyiwei850/dsh-ssh-ops/releases)

---

## 1. 这是什么

**DSH SSH Ops** 是 DeepSeek Harness（DSH）的 SSH 运维插件。装上之后，DSH 会多出一个右侧边栏标签——一台真正的交互式 SSH 终端；同时主对话里的 AI 助手获得一整套运维工具（连接、执行命令、传文件、查数据库、建隧道、批量执行），可以和你并肩操作同一台服务器。

它不是「把命令行搬进聊天框」，而是**双轨并行**：

- **你**：右侧终端手工操作，跟平时用 ssh 一样，历史回看、随时介入；
- **AI**：主对话里接活，把命令下到服务器上执行，过程和输出直接显示在右侧终端里，你全程看得见。

![主对话与官方侧栏中的 SSH 终端](../assets/screenshots/official-sidebar-terminal.png)

## 2. 给谁用、解决什么问题

| 你的处境 | 这个插件给你的东西 |
| --- | --- |
| 想让 AI 帮忙运维服务器，但担心它乱删东西 | 高危命令黑名单 + 删除进回收站 + 危险 SQL 自动备份，AI 永远无法真正删库 |
| 受够了在聊天窗口里贴终端输出、复制粘贴命令 | AI 直接在服务器上执行，命令与回显实时镜像到右侧真实终端 |
| 多台机器来回切换、重复输入密码 | 服务器资源统一管理、凭据加密存本机、共享凭据一处改全局生效 |
| 内网数据库查个数据要开隧道、装客户端 | 数据库面板直连 MySQL/PostgreSQL/Redis/MongoDB 等，回环地址自动走 SSH 隧道 |
| 十台机器跑同一条命令 | 「批量执行」一句话发起，勾选目标机器，一键并发下发 |
| 跳板机后面的网络设备/深层机器 | ProxyJump 链最多 8 跳，SSH Agent 转发免铺私钥 |

**适用角色**：后端/运维/数据工程师，以及任何「日常要摸服务器，又想让 AI 打下手」的人。不需要懂插件开发；需要的基础只有一条——知道服务器地址和账号。

## 3. 功能全景

装好后，右侧边栏出现 **SSH 标签**，内含五个页签：

| 页签 | 干什么 | 对应 Agent 工具 |
| --- | --- | --- |
| **终端** | 交互式 PTY 终端，多标签、明暗主题跟随、回看缓冲 | `ssh_exec` / `ssh_read` / `ssh_write` |
| **文件** | SFTP 文件管理器：浏览、上传下载、拖拽、文本编辑 | `sftp_*`（8 个） |
| **转发** | 本地/远程/SOCKS5 动态端口转发，实时查看与停止 | `tunnel_*`（3 个） |
| **数据库** | 连接数据库，跑 SQL/命令，表格化结果，导出 CSV | `db_*`（15 个） |
| **日志** | 终端会话录制：预览、搜索、下载、删除 | `ssh_session_log_*`（3 个） |

配套的 **设置 → SSH 资源** 是服务器资产管理页（与通用设置并列的一等菜单），内含三段：**服务器分组**、**共享 SSH 凭据**、**AI 命令执行策略**。

主对话里的 AI 共获得 **40 个工具**（详见附录总表）。

## 4. 安装

### 前置条件

- 已安装 **DSH Desktop**（或 Web Profile）。插件使用 DSH 自带的 Node.js 运行时，**不要求**系统另装 `ssh`/`sftp`/Node。
- 宿主需提供新版右侧边栏 API（`sidebarRightTabs` / `sidebarRight`），SSH 终端以官方侧栏标签运行，支持分栏、缩放、全屏。

### 三种安装方式

**GitHub 渠道（推荐）**：

```bash
dsh plugin --profile web add github:caoyiwei850/dsh-ssh-ops#v0.3.22
```

装的是源码，安装期自动构建。注意 pnpm ≥ 10 默认拦截依赖构建脚本——若重启后 SSH 标签没出现，进 `node_modules/dsh-ssh-ops/` 手动执行 `npm install && npm run build` 后再重启（详见 [INSTALL.md](../INSTALL.md)）。

**发布压缩包**：从 [Releases](https://github.com/caoyiwei850/dsh-ssh-ops/releases) 下载 `.tgz` 后 `dsh plugin --profile web add /path/to/dsh-ssh-ops-x.y.z.tgz`。

**离线审阅/二次开发**：下载 `.zip` 解压，`npm install` 即可（构建自动完成）。

### 必做：重启

安装或升级后**完整退出并重启 DSH**（系统托盘 → 右键 → 退出）。不重启，宿主半不加载。

### 升级

插件界面的 **设置 → SSH 资源 → 通用** 里有自更新条（版本徽标、检查更新、一键更新）。SSH 资源、已知主机指纹、凭据都存在 DSH 独立本地存储，不在插件包内，常规升级不丢数据。

## 5. 十分钟上手

### 第 1 步：添加一台服务器

**设置 → SSH 资源 → 新建服务器**，填名称、主机、端口、用户名、认证方式（密码 / PEM 私钥，密钥文件可直接拖入窗口）。建议顺手填一个**分组**（如「生产」「测试」）方便日后筛选。

![SSH 资产管理](../assets/screenshots/ssh-resources.png)

几个常用高级选项（都在表单底部「高级选项」折叠区）：

- **项目目录**：填一个绝对路径，资源卡片上会多出「进入项目」按钮，一键连接并切到该目录；
- **登录命令**：替代默认 shell 打开终端（如服务器默认 shell 不兼容时填 `bash -l`，或固化 `tmux attach`）；
- **跳板机**：从已保存的服务器里选一台当前置，最多 8 跳；
- **SSH Agent 转发**：勾上后，跳板机上可继续用本机密钥登录更深层的机器；
- **双因素认证**：设备要求 `password,publickey` 组合认证时，为密码/私钥配一条相反类型的第二因素。

点资源卡片上的「**连接并打开**」——右侧弹出终端，完成。

### 第 2 步：第一次连接会校验主机指纹

首次连接记录服务器公钥指纹（TOFU 模式），之后指纹变化即拒绝——防止中间人或误连重装机。指纹变化时不会自动重试，按提示「忘记指纹」重置即可。

### 第 3 步：让 AI 接活

在主对话里直接说人话：

> 「看下这台机器的内存和磁盘占用」
> 「把 Nginx 配置里的 server_name 改成 api.example.com 然后重载」

AI 会把命令下发到当前连接的服务器，**命令和回显实时出现在右侧终端**，并回报退出码、耗时、当前目录。你随时可以在终端里手动接管。

> ⚠️ **AI 默认摸不到你的家底**：不能枚举已保存的服务器，也不能用保存的凭据自己连别的机器。想让它按名字连接某台已保存服务器，需在 **设置 → SSH 资源 → AI 自动连接** 打开开关（打开后每次连接都会在右侧面板开终端，操作者始终可见）。

### 第 4 步：管文件

右侧「文件」页签就是 SFTP 文件管理器：上传、下载、新建目录、删除、重命名、拖拽上传、内置文本编辑器（10 MB 内）、收藏路径。也可以直接对 AI 说「把这个目录下载到本地」。

![官方侧栏中的 SFTP 文件管理与 cd](../assets/screenshots/official-sidebar-files-cd.png)

### 第 5 步：查数据库

「数据库」页签新建连接，支持 **MySQL / PostgreSQL / Redis / MongoDB / SQLite / ClickHouse / openGauss** 七种。关键设定：

- 数据库地址填回环地址（127.0.0.1 等）时**自动经当前 SSH 服务器隧道**访问内网库，不用手动开隧道；
- SSL 三档可选（不加密 / 加密不验证 / 加密+验证 CA），适配云托管数据库；
- 连接可保存为资源，重启后一键重连。

![数据库管理界面](../assets/screenshots/db-panel.png)

也可以让 AI 来：`db_query` 是词法级强制只读（只放行 SELECT/SHOW/DESCRIBE/EXPLAIN/纯查询 WITH），写操作走 `db_execute`，高危 SQL（DROP/TRUNCATE/SHUTDOWN）一律拦截并自动备份。

### 第 6 步（进阶）：端口转发与批量执行

- 「转发」页签或对话里建隧道：本地转发、远程转发、**SOCKS5 动态转发**（`ssh -D` 等价物，一个本地端口当代理出口）；
- 多机批量：主对话说「**批量执行** df -h」，AI 创建批量任务，右侧弹出勾选弹窗（列出全部已保存服务器，**含未连接的**），勾选确认后并发执行，结果按服务器分节展示。

## 6. 功能详解

### 6.1 连接管理

- **资源化**：服务器信息（名称/地址/端口/用户名/认证/分组）保存到 DSH 本地存储，数量不设上限；密码、PEM 私钥、私钥口令只进 DSH 官方本机凭据库 `~/.dsh/.credentials.yaml`（owner-only 权限），浏览器存储、AI 上下文、工具结果都**不会**读取或显示秘密内容。
- **共享凭据**：一份密码/私钥存为共享凭据，多台服务器与跳板机共同引用——全组共用一把运维私钥时改一处即全部生效；仍被引用时拒绝删除。
- **连接稳定性**：keepalive（20 秒×3 次）防 NAT 静默断连；传输意外断开指数退避自动重连（上限 30 秒），命令中途掉线透明重试一次；对端 SSH 横幅不合 RFC 4253（如 `SSH-2.0- OpenSSH` 多个空格）时自动规范化重试一次。
- **网络设备支持**：华为 VRP / 华三 Comware / Cisco 等网络 CLI 设备上，`ssh_exec` 自动识别提示符、推进分页（`---- More ----`），以提示符回归为完成信号，不再 15 秒超时返回空输出。
- **每栏独立通道**：官方分栏时每个窗格各自维护服务器与连接；同一台服务器两栏各开一条独立连接（可在连接对话框勾选「复用已打开的连接」共用一条）。

### 6.2 AI 协作

- **可见、可切换的作用目标**：被 AI 使用的连接带「**Agent**」徽标；点另一栏的服务器标签即把 AI 切过去。
- **主对话自动识别**当前连接，不需要你找内部连接 ID。
- **AI 的命令看得见**：`ssh_exec` 的命令显示在右侧终端，回报退出码/输出/cwd/耗时/超时/截断状态；能唯一确认空闲交互 shell 时继承其实际目录。
- **不偷看你的终端**：手动终端内容不会静默进入对话上下文；AI 需要时经**每次用户确认**，通过 `ssh_terminal_context` 按游标读取有限的、脱敏的历史。
- **输出脱敏**：回传给模型前自动抹除私钥、Bearer Token、`sk-` 开头的 API Key、数据库连接口令等。
- **会话日志**：「日志」页签录制终端会话（预览/搜索/下载/删除；单会话 8 MB、目录 256 MB 自动轮换），AI 也有 `ssh_session_log_search` 等工具按需检索。

### 6.3 AI 命令执行策略（重要）

这是你给 AI 上权限的旋钮，在 **设置 → SSH 资源 → AI 命令执行策略** 配置，三个档位：

| 档位 | 行为 |
| --- | --- |
| **标准**（默认） | 高危命令（删文件、删库、格式化、重启等 8 类）一律拦下，弹确认卡片由操作者定夺 |
| **自定义放行** | 在 8 个类目里勾选放行哪些（如只放行「重启或关闭服务器」） |
| **全部放行** | AI 命令全部直接执行——**放行的命令按原样执行，删除不再进回收站**，请确认风险后再开 |

规则要点：

- **AI 永远无法自行放宽档位**——切换档位是操作者专属操作，AI 尝试时只会收到结构化拒绝；
- 会话内切换（终端左下角的档位贴片，默认收缩为贴边色点，悬停展开）**只对本次会话生效**；往宽松方向切换需二次确认；要按机器长期覆盖，在该服务器资源的「高级选项」里设置；
- 多机批量的操作者勾选闸门**不受档位影响**，永远要走确认。

8 个高危类目：删除文件或目录 / 批量删除文件 / 删除数据库数据或对象 / 格式化或改写磁盘 / 删除容器镜像或卷 / 销毁已部署资源 / 不可恢复地清理代码工作区 / 重启或关闭服务器。

### 6.4 安全模型（三层防线）

**第一层：黑名单拦截。** AI 工具执行明显不可逆操作（删库、格式化、`terraform destroy`、`kubectl delete`、`docker prune`、强制 Git 清理、重启/关机等）直接拦截；黑名单覆盖高频绕过变体（`find -exec rm`、`xargs rm`、`rimraf`、python/perl/node 一行流调 `unlink`/`rmtree`）。

**第二层：删除可逆化。** 简单 `rm`/`unlink`/`rmdir` 经确认后执行的是**可恢复的移动**：目标进服务器上的 `~/.dsh-trash/` 并记录原路径，24 小时后过期项在下一次有新文件进站时顺带真删（不在服务器上装定时任务）。**AI 发起的删除永远不会真正发生**——误删能从回收站 `mv` 回来；彻底删除由人自己在终端执行 `rm`（人工输入不经过拦截）。

**第三层：危险 SQL 可恢复化。** `DROP`/`TRUNCATE`/`SHUTDOWN` 一律不执行，拦截瞬间**自动备份**受影响的表（含建表 DDL）；其中 `DROP TABLE` 进一步转为**隔离改名**（`<表名>_to_be_dropped_<日期>`），数据原样保留，最终的真 DROP 只接受面板人工发起。

命中黑名单时会**全视口弹出确认模态**（完整命令 + 风险原因），不处理常驻在终端上方；危险命令**绝不预填**到终端命令行，不存在误按回车执行的可能。

### 6.5 数据库工程化

- `db_query` 词法级**真只读闸**：拦截写动词子查询、PG 数据修改 CTE、`SELECT INTO`、`FOR UPDATE` 锁读；不误杀字符串字面量里的关键字；
- 流式截断默认 200 行 + 30 秒超时（环境变量 `DSH_SSH_OPS_MAX_DB_ROWS` 最多调 5000）；连接级 `query_timeout_ms` 可为慢库放大超时（`0` 为不限）；
- 交互式事务 `db_tx_begin/execute/commit/rollback`（独占连接、闲置 5 分钟自动回滚）；
- `db_describe_table`（列/索引/外键/DDL/行数）、`db_explain`（执行计划）、`db_preview`（分页采样）、`db_export`（CSV/JSON 导出，可经 SSH 落到服务器再由文件页签取回）；
- 面板侧：表树、预览视图、一键导出 CSV（含 BOM，Excel 中文兼容）、查询历史 50 条。

### 6.6 界面语言

自动跟随 DSH 自身语言（中文/English），运行中切换即时重绘。宿主语言插件未内置（如俄语）时回退中文——此类环境可在设置文件（`~/.dsh/storages/ssh_ops_settings.json`）设 `autoApplySystemLanguage: false` + `language` 钉住语言（编辑需在 DSH 停止时进行）。

## 7. 典型场景配方

**上线前巡检**——「连上 prod-web-1，看下磁盘、内存、最近 100 行应用日志有没有报错」；巡检类命令属普通运维操作，正常执行。

**排查磁盘满**——AI `df -h` 定位 → `du` 逐层下钻 → 建议删除大文件时弹出确认卡片 → 你点「执行」，文件进回收站而非真删，确认业务无碍后再清回收站。

**跳板机后面的内网库**——服务器资源里把跳板机配好 → 数据库连接地址填内网回环地址 → 自动经 SSH 隧道连接，`db_query` 直接查。

**给 20 台机器统一改配置**——「批量执行 cat /etc/os-release | head -1 先看系统版本」→ 勾选目标 → 逐台核对结果 → 再批量下发修改命令。

**临时给同事开个代理出口**——「在 jump-server 上建一个 SOCKS5 动态转发，本地 1080 端口」→ 转发页签出现隧道，用完一键停止。

**备份一张表再动结构**——`db_execute` 发起 `DROP TABLE` → 插件拦截并自动备份 CSV + DDL → 表被隔离改名而非删除 → 确认无误后由你在面板人工执行最终删除。

## 8. 常见问题

**装完没看到 SSH 标签？**
① 完整退出重启 DSH 了吗；② GitHub 渠道 + pnpm ≥ 10 的环境检查 `node_modules/dsh-ssh-ops/lib/` 是否存在（缺失 = 构建被拦，进包目录 `npm install && npm run build`）。

**AI 说「无法枚举已保存资源」？**
预期行为。打开 **设置 → SSH 资源 → AI 自动连接** 后，AI 才能按名称连接已保存服务器。

**AI 想删东西被拦了，我确认安全，怎么办？**
在弹出的确认卡片上人工点「执行」——简单删除此时进回收站（可恢复）；或到执行策略里按类目放行；或你自己在终端执行。

**认证失败？**
插件会给出结构化诊断（试过哪些方法、服务器还接受什么、下一步建议）。常见原因：私钥被截断、公钥未加到服务器 `authorized_keys`、加密私钥的口令填进了密码槽。

**终端不动了 / 画面冻结？**
多为宿主重启杀掉了旧 SSH 会话，旧终端画面已死。关掉该终端标签重开一个即可。

**指纹变化被拒？**
先确认不是中间人、也确实没连错机器（比如这台机器重装了系统），再到 **设置 → SSH 资源 → 已信任主机** 里「忘记指纹」后重连。

**数据库大查询被 30 秒掐断？**
连接时设 `query_timeout_ms`（`0` 为不限），或在资源里保存该设置。

## 9. 附录：Agent 工具总表（40 个）

省略 `connection_id` / `db_connection_id` 时默认作用于当前活动连接，无需先列连接。

**SSH 会话（7）**：`ssh_list` 列出连接元数据与（开关开启时）已保存资源 · `ssh_connect` 建立连接 · `ssh_connect_profile` 按名称连接已保存资源（需 AI 自动连接开关）· `ssh_exec` 执行命令 · `ssh_read` 按需读终端缓冲 · `ssh_write` 向终端写入交互输入 · `ssh_disconnect` 断开

**手动终端上下文（3）**：`ssh_terminal_sessions` 列出终端游标元数据 · `ssh_terminal_context` 经每次确认读取脱敏历史 · `ssh_shell_integration` 在 bash/zsh 里启用 OSC 133 集成（此后能读到 cwd/退出码/提示符状态）

**会话日志（3）**：`ssh_session_log_list` / `ssh_session_log_read` / `ssh_session_log_search`

**SFTP（8）**：`sftp_list` · `sftp_read`（默认上限 4 MiB）· `sftp_write` · `sftp_mkdir` · `sftp_delete`（不直接执行，进确认队列/回收站）· `sftp_rename` · `sftp_upload_dir` · `sftp_download_dir`（目录批量，小文件并发、大文件独占、单文件失败不断整批）

**端口转发（3）**：`tunnel_start`（`local` 本地 / `remote` 远程 / `dynamic` SOCKS5）· `tunnel_list` · `tunnel_stop`

**批量执行（1）**：`ssh_batch`——仅当用户明确要求多机批量时使用，操作者勾选确认后并发下发

**数据库（15）**：`db_connect` · `db_list_connections` · `db_query`（强制只读）· `db_execute`（写操作，高危拦截+备份）· `db_list_tables` · `db_describe_table` · `db_preview` · `db_explain` · `db_export` · `db_run`（Redis 命令 / MongoDB 操作）· `db_disconnect` · `db_tx_begin` / `db_tx_execute` / `db_tx_commit` / `db_tx_rollback`
