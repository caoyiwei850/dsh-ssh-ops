# 终端语义高亮：刷新与故障恢复

本文说明实时终端高亮的刷新策略与维护约束。用户设置和渲染边界见[终端显示说明](./terminal-display.md)。相关实现位于 `src/client/terminal-display/`。

## 刷新触发与结果采用

xterm 5.5 的用户滚轮和滚动条路径会抑制 `onScroll`。因此，仅订阅该事件无法保证滚动历史后重新着色。`addon.js` 同时监听渲染后的 `viewportY` 变化，并以 250 ms 轮询兜底；resize、buffer 切换和配色更新则使旧扫描失效并请求重算。

写入与滚动事件以 60 ms 的 leading throttle 合并，不会反复推迟扫描，也不会仅因新输出到达而丢弃进行中的结果。扫描前注册 xterm marker，worker 返回后按 marker 的行号变化重定位结果；锚点行本身被 scrollback 裁掉时，才丢弃该结果并重新扫描。临时 marker 在 `finally` 中释放。

## 渲染预算

- 每次最多扫描 200 个可见物理行、注册 1024 个装饰，优先保留底部最新输出的颜色；密集视口的顶部行可能保持普通前景色。
- 逻辑行读取限制为 16384 个 cell，自动换行回溯限制为 256 行，极长行可能仅部分着色。
- 未变化的行复用 marker 和装饰；读取字符时复用 xterm cell，减少分配。
- alternate screen 中不绘制语义装饰；远端已有 ANSI/truecolor 和字体样式优先。

普通写入不会作废进行中的扫描，所以就地覆盖同一行时可能短暂沿用旧颜色，下一次扫描后收敛。大批量输出或 resize 期间也可能短暂重建装饰。上述处理只影响显示，不改变终端字节、复制文本、搜索或会话日志。

## Worker 生命周期与故障恢复

终端和预览共享一个串行 worker，按调用方合并排队任务。单个终端释放不会直接重启其他终端正在使用的 worker；释放时遗留任务的 watchdog 可回收挂死 worker。

worker 启动等待上限为 2500 ms，启动后每个匹配任务的时限为 150 ms。超时方案隔离 30 秒，编辑配色也可解除隔离。worker 不可用时不回退到主线程执行正则。

扫描失败保留上次成功的装饰，按 500 ms、1 s、2 s、5 s 退避，同一错误原因只告警一次；编辑配色清除退避并立即请求刷新。装饰 API 异常会停用该终端的语义高亮，主题切换和终端输入输出仍可使用。

## 自动回归

```sh
npm run build
node --test test/output-highlight.mjs test/highlight-refresh.mjs test/regex-worker.mjs
npm test
npm run lint
git diff --check
```

`test/highlight-refresh.mjs` 覆盖滚轮式视口移动、无渲染事件时的轮询、扫描期间写入、scrollback 裁剪重定位、锚点丢失、底部优先预算、共享 worker 释放、挂死回收、隔离过期和失败退避。其他特性测试覆盖 ANSI 与 Unicode、持久化、主题同步、正则超时和预览匹配。

## 宿主验收步骤

1. 连接测试 SSH 服务器，在「终端外观」中启用语义高亮。
2. 在测试终端输出带关键词、时间和地址的多行文本，例如：

   ```sh
   seq -f 'L%g 2026-11-06 12:00:00 ERROR 10.1.2.3 /var/log/app.log' 1 20000
   ```

3. 输出期间检查颜色持续出现；结束后使用滚轮、滚动条翻阅历史，并调整窗口大小，可见行应重新着色。
4. 输出超过 scrollback 容量后继续翻阅，检查装饰没有落到错误行。
5. 进入 `vim` 或 `top` 检查不装饰，退出后检查高亮恢复。
6. 打开两个终端或分栏，关闭其中一个后检查另一个仍能刷新；验证选择、复制和搜索文本不变。

自动回归不代替 DSH 宿主内的交互验收；具体版本的实测结果应随 PR 验证记录提供。
